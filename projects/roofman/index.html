PROJECT 01

ROOFMAN

A scroll-driven roof restoration experience where damage heals as you move down the page, built as a cinematic product demo.

Live Website All Projects
roofman.pages.dev
01. The Idea

The Idea

Roof restoration is hard to show in a static brochure. Roofman turns the repair into something you watch: as you scroll, damaged roof frames give way to a healed surface, so the product story lands through motion instead of another feature list.

02. What I Built

What I Built

I built a React and Vite demo that ties scroll progress to a frame sequence of the roof healing, with supporting video and a layout that stays readable on phones. The page is deployed on Cloudflare Pages so the live demo stays fast to open and share.

  • Scroll-driven restoration sequence
  • Frame-based roof heal animation
  • Cinematic product storytelling
  • Timelapse video support
  • Responsive layout
  • Cloudflare Pages deployment
03. User Experience

User Experience

The first job of the page is to make someone pause and keep scrolling. Progress is tied to the heal animation, so each scroll step feels like part of the restoration rather than a jump between disconnected sections.

04. Design Decisions

Design Decisions

The visual system stays quiet so the roof frames stay in charge. Typography and spacing support the cinematic feel without covering the media, and the layout keeps the call to continue scrolling obvious on both desktop and mobile.

05. Technical Approach

Technical Approach

Built with React and Vite, with scroll position driving which restoration frame is shown. Preloading key media keeps the sequence from stuttering, and Cloudflare Pages serves the static build without a custom server to maintain.

06. SEO Perspective

SEO Perspective

The live demo is a product experience first, so the portfolio case study carries the crawlable title, description and structured data. Clear naming and a stable live URL make the project easy to cite and share.

07. What I Learned

What I Learned

Scroll-linked media only works when frame timing and asset weight are treated as part of the design. Too few frames feels jumpy; too many makes the first load heavy. The useful middle is a sequence that reads as continuous without asking the visitor to wait.
